# v3.3.1 — Group search fix

Fix erroneous `LINE_SEARCH_NOT_UNIQUE` refusals when LINE labels group results as chats and truncates long names.

- A single structural group result is a navigation candidate only. The detached window must have the complete exact title.
- Refresh the bound chat, own account, group type and name uniqueness before composer input; retain the pre-send check.
- Identity-only reads now return the checked `ownSenderRef` when supplied. Wrong accounts still refuse.
- Direct-chat behavior, tool schemas, dependencies and no-resend journals remain unchanged.

Validation: 353 Node tests passed; Python ran 136, with 128 passed and eight environment skips. Live group search/open/identity/empty-composer preparation completed in 10.266 seconds. No message was typed or sent in this group acceptance check. Runtime code matches installed `3.3.1-local.1`. The focused patch security review found no confirmed vulnerabilities; it is not a repository-wide security guarantee.

Window titles and local records are independent evidence, not a direct window-to-database identifier. Qt accessibility can be partial. Multiple rows or an unsupported structure retain the existing full-name validation path; unresolved identity refuses. Private chats, screenshots and diagnostic receipts are excluded from the public package.
