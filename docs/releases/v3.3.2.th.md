# v3.3.2 — ตรวจหน้าต่าง LINE และผลค้นหา

2026-09-28 (Asia/Taipei)

แท็บหมวดหมู่ต้องตรงกันทุกคำจาก OCR ระดับคำ เพื่อไม่ให้บรรทัด OCR ที่รวมกันถูกเข้าใจว่าเป็นแท็บ การนำทางจากผลลัพธ์หนึ่งรายการสำหรับแชตส่วนตัวต้องมีคำค้นตรงกัน แท็บ Friends ที่เลือกอยู่ จำนวนและแถวในส่วนแชตอย่างละหนึ่งรายการ โดยแยกผลประวัติข้อความออกต่างหาก และชื่อเต็มของหน้าต่างแยกที่ตรงกัน หน้าต่าง LINE หลักต้องมีโครงสร้าง UIA ครบทั้งแถบนำทาง แถบข้าง split pane ตัวแบ่ง ช่องค้นหา และรายการ หน้าต่างเสริมที่กำกวมจะถูกปฏิเสธ การคืนหน้าต่างที่ย่อไว้ใช้ HWND/PID/ชื่อที่พิสูจน์โครงสร้างแล้วเท่านั้น และตรวจซ้ำหลังคืนหน้าต่าง OCR ของผลค้นหาตัดจากภาพหน้าจอที่สังเกตไว้ภาพเดียว แล้วแปลงพิกัดกลับเป็นภาพเต็ม

ไม่เปลี่ยน dependencies, schema ของเครื่องมือ, CLI หรือบันทึกป้องกันส่งซ้ำ Windows ยังแสดงเครื่องมือใช้งาน 33 รายการและ alias เดิมที่ซ่อน 5 รายการ ผลส่งที่ไม่แน่นอนจะไม่ส่งซ้ำอัตโนมัติ

การทดสอบ Node ผ่าน 374/374 รายการ Python ไม่เปลี่ยนจาก v3.3.1 โดยใช้ผลก่อนหน้า 136 รายการ ผ่าน 128 และข้ามตามสภาพแวดล้อม 8 รายการ ไม่ได้รันใหม่ในแพตช์นี้ การทบทวน diff ด้านความปลอดภัยที่ปิดแล้วไม่มีข้อค้นพบที่ต้องรายงาน และการทบทวนอิสระของ diff การค้นหาแบบผสมที่เพิ่มภายหลังไม่พบข้อบกพร่องด้านความปลอดภัยที่ต้องแก้ ทั้งสองครั้งจำกัดเฉพาะการเปลี่ยนแปลงในรีลีสนี้

ชื่อหน้าต่างกับตัวตนใน DB ภายในเครื่องเป็นหลักฐานอิสระ ไม่ใช่การจับคู่ HWND กับ DB โดยตรง ข้อมูล accessibility ของ Qt อาจไม่ครบ และจะปฏิเสธโครงสร้างที่ไม่ชัดเจน การตรวจจริงก่อนหน้านี้ครอบคลุมการคืนหน้าต่างย่อด้วย HWND ที่ตรงกัน และการเตรียมแชตส่วนตัว/กลุ่มจนได้หน้าต่างแยกที่ชื่อเต็มตรงกันและช่องพิมพ์ว่าง แม้มีหน้าต่างเสริมอยู่ การตรวจ Friends search แบบผสมภายหลังพบผลแชตหนึ่งรายการกับผลประวัติข้อความอีกสี่รายการในส่วนแยกกัน จากนั้นเปิดหน้าต่างแยกที่ชื่อเต็มตรงกับคำขอโดยคงช่องว่างเดิม ตรวจตัวตนในเครื่องอีกครั้ง และพบช่องพิมพ์ว่าง การกระทำมีเพียงคลิกค้นหา แท็บ แถวผลลัพธ์ และหน้าต่างแยก ไม่มีการพิมพ์หรือส่งข้อความ OCR หมวดหมู่ครั้งแรกปฏิเสธชั่วคราว แต่ลองใหม่หลังสังเกตหน้าการนำทางที่ถูกต้องแล้วผ่าน การเน้นสีเขียวอย่างเดียวไม่ใช่หลักฐานตัวตนแชต และไม่รับประกันรูปแบบ OCR ทั้งหมด
