# v3.0.1 — 本機讀取器串流修復

![LINE Agent MCP](../assets/line-agent-cover-v3.png)

v3.0.1 是 Issue #1 的修補版，修正本機讀取器只因資料庫超過舊版 256 MiB 整檔讀取上限而拒絕的問題。本版不新增 MCP 工具、UI 行為或安全功能擴充；v3.0.0 的前置條件與操作限制持續適用。

## 修正內容

- 加密資料庫現在以 1 MiB 串流區塊讀取。預設預算為資料庫 2 GiB、WAL 256 MiB，以及合併快照 2304 MiB；三項上限仍可在有界範圍內設定。
- 讀取器開啟複製後的快照前，仍會保留資料庫／WAL 穩定性檢查、最新已提交 WAL 檢查及工作階段金鑰重新驗證。
- 讀取器預設逾時為 300 秒，且可設定。每個請求只擁有一個精確的暫存目錄；固定快照檔案只會在確認子程序已結束後清理。若無法確認終止，目錄會保留，不會宣稱已清乾淨。

## 驗證與限制

候選版本通過 234 個 Node 測試與 125 個 Python 測試中的 124 個；唯一跳過的是測試帳號沒有權限執行既有的 Windows 檔案符號連結測試。原生加密測試皆有執行。合成讀取以 853,438,464 位元組資料庫加 4,152 位元組 WAL，以及 1,087,713,280 位元組資料庫加相同 WAL，驗證最新已提交結果、來源雜湊未改變與暫存目錄清理。這些測試資料觀察到的程序尖峰工作集約為 39 MiB，不能當作一般效能保證。

讀取器仍會在查詢前複製完整的已界定來源資料庫，並非只複製某頁或某日期。此次驗證中的 LINE 版本識別與金鑰取得使用模擬；未執行真實 LINE 聊天讀取、送出端對端流程或提出 Issue 的使用者環境驗證。

## 升級

使用 GitHub `v3.0.1` 標籤或附件 `line-desktop-mcp-3.0.1.tgz` 與 `SHA256SUMS.txt`；不發佈到 npm 套件庫或 MCPB。請解壓縮到新的同層目錄，在該套件目錄執行 `npm ci --ignore-scripts`，將啟動器指向新目錄後重新連線 MCP 用戶端並刷新結構描述。不需要刪除或遷移 LINE 資料庫。保留舊套件與啟動器以便回退。
