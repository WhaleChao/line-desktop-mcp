# v3.2.0 — 有範圍限制的 LINE 工作流程

2026-09-23 · [CLI](../CLI.md) · [升級與回退](../MIGRATING.md#upgrading-to-v320)

Windows MCP 現在會將普通文字傳送結果，與指定聊天室本機 DB/WAL 中新出現的本人訊息核對。操作期限為 30 秒，其中 25 秒用於輸入，保留 5 秒查核本機紀錄。`RECORDED_LOCAL` 只代表找到相符的本機紀錄，**不代表**對方收到或已讀。持久化的冪等紀錄會避免自動重複傳送；結果不確定時，使用同一個 `idempotencyKey` 重查，只會唯讀檢查先前紀錄。刻意再傳一次需要新的 key。

MCP 讀取、搜尋、匯出與核對，只要指定單一日期，或完整的 `dateFrom`／`dateTo`（最多 31 天），就使用共用的指定範圍本機讀取器。未指定日期的舊用法仍讀取 LINE 介面已載入的歷史。`compareWithUi: true` 會另行要求介面比對，可能將聊天室標為已讀。本機快取不等於完整的伺服器歷史。

傳送時會綁定精確的聊天室身分和本人發話者身分。即使同名聯絡人之一尚無聊天列，名稱衝突也會拒絕；按 Return 前會立即重查身分。獨立聊天室及檔案選擇器會核對視窗控制代碼、程序 ID 和標題。`send_file_manual` 只在選擇器中暫存附件；經使用者同意後點擊「開啟」才會實際傳送。Windows 擴充工具清單顯示 26 個目前使用的工具；另外 5 個舊別名仍可呼叫但不列出，總共有 31 個實作描述。回傳內容縮短，Ajv 在擴充功能使用時才載入。唯讀 `line-cli` 保留原有指定範圍的 JSON／TXT／CSV 指令，不操作 LINE。

實際 MCP 檢查涵蓋指定日期讀取、搜尋與核對，該次觀察每項約 0.6 秒；TXT／JSON／CSV 匯出各核對到一筆紀錄。這是單次觀察，不是通用速度保證。引導式視覺檢查涵蓋個人與群組文字及本機回執、真正的藍色提及、引用回覆、轉傳與收回、合成 TXT／PNG 附件暫存及媒體讀回、投票、筆記、相簿、表情回應、通知與視窗切換、開啟貼圖面板，以及開啟後取消擷取面板。這些豐富功能是引導式介面操作檢查，**不是**自主執行的 MCP 工具流程。引導式介面精確複製與英文翻譯已通過檢查，但直接 MCP 定位自繪文字仍可能拒絕。引導式 Files、Media、Links 介面操作已通過；MCP Files 功能入口只開啟「更多」選單，找不到 Files 並回傳 `LINE_FEATURE_UNAVAILABLE`，不會自動開啟 Files 面板。聊天室清單釘選已實測關→開→關並還原。下載的 TXT 檔案與來源 SHA-256 完全一致。`get_line_draft` 透過 Search 開啟後，對個人與群組空白草稿的實機讀取皆通過；該次觀察約 2.3 秒。

本版透過 GitHub 原始碼 tag 與附件 `line-desktop-mcp-3.2.0.tgz` 發布；沒有 npm registry 或 MCPB 發布。
