# v3.0.1 — แก้ไข local reader แบบสตรีม

[ทุกภาษา](README.md) · [ดาวน์โหลด](https://github.com/bensonmaxai/line-desktop-mcp/releases/tag/v3.0.1) · [การติดตั้ง](../quickstart-windows.md) · [การย้ายและย้อนกลับ](../MIGRATING.md#upgrading-to-v301)

![LINE Agent MCP](../assets/line-agent-cover-v3.png)

v3.0.1 เป็น patch release สำหรับ Issue #1 แก้ปัญหา local reader ปฏิเสธฐานข้อมูลเพียงเพราะเกินขีดจำกัดการอ่านทั้งไฟล์ 256 MiB เดิม รีลีสนี้ไม่เพิ่ม MCP tools, พฤติกรรม UI หรือฟีเจอร์ความปลอดภัยใหม่ ข้อกำหนดเบื้องต้นและขอบเขตการใช้งานของ v3.0.0 ยังคงใช้ต่อไป

## สิ่งที่เปลี่ยน

- ข้อมูลฐานข้อมูลที่เข้ารหัสจะอ่านเป็น streamed chunks ขนาด 1 MiB งบประมาณค่าเริ่มต้นคือ database 2 GiB, WAL 256 MiB และ combined snapshot 2304 MiB ทั้งสามขีดจำกัดยังตั้งค่าได้ภายในเพดานที่จำกัด
- การตรวจความเสถียรของ database/WAL, การตรวจ WAL ที่ commit ล่าสุด และการตรวจ session key ซ้ำก่อน reader เปิด snapshot ที่คัดลอกไว้ ยังคงอยู่
- timeout เริ่มต้นคือ 300 วินาทีและปรับได้ แต่ละคำขอใช้ไดเรกทอรีชั่วคราวแยกกัน ปกติโปรเซสลูกจะล้างไฟล์สแนปช็อตของตนเอง ส่วนโปรเซสแม่จะล้างไฟล์ที่เหลือหลังยืนยันว่าโปรเซสลูกจบแล้วเท่านั้น หากยังยืนยันไม่ได้ โปรเซสแม่จะเก็บไดเรกทอรีไว้จนกว่าโปรเซสลูกจะจบ

## การตรวจสอบและข้อจำกัด

release candidate ผ่าน Node tests 234 รายการ และ Python tests 124 จาก 125 รายการ skip เดียวคือ existing Windows file-symlink privilege test ที่บัญชีทดสอบไม่มีสิทธิ์ Native crypto tests รันครบ การอ่าน synthetic ด้วย database 853,438,464-byte กับ WAL 4,152-byte และ database 1,087,713,280-byte กับ WAL ชุดเดิม ยืนยันผลที่ commit ล่าสุด, source hash ไม่เปลี่ยน และ temporary directory ถูกล้าง fixture เหล่านี้พบ process peak working set ราว 39 MiB ซึ่งไม่ใช่สัญญาประสิทธิภาพทั่วไป

reader ยังคัดลอก scoped source database ทั้งชุดก่อน query ไม่ได้คัดลอกเฉพาะ page หรือ date ในการตรวจสอบนี้ build และ key discovery ใช้ mock ไม่มีการอ่าน LINE chat จริง, flow ส่งแบบ end-to-end หรือการทดสอบบน reporter machine

## การอัปเกรด

ใช้ GitHub tag `v3.0.1` หรือไฟล์แนบ `line-desktop-mcp-3.0.1.tgz` และ `SHA256SUMS.txt`; ไม่มีการเผยแพร่ผ่าน npm registry หรือ MCPB แตกไฟล์ลงใน sibling directory ใหม่ แล้วรัน `npm ci --ignore-scripts` ภายใน package directory นั้น ชี้ launcher ไปที่ directory ใหม่ เชื่อมต่อ MCP client ใหม่และ refresh schema ไม่ต้องลบหรือย้าย LINE database เก็บ package และ launcher เดิมไว้สำหรับ rollback
