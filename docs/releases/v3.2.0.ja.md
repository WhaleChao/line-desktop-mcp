# v3.2.0 — 範囲を限定した LINE ワークフロー

2026-09-23 · [CLI](../CLI.md) · [更新とロールバック](../MIGRATING.md#upgrading-to-v320)

Windows MCP の通常テキスト送信は、正確に指定したチャットと自分の送信者 ID に結び付け、ローカル DB/WAL の新しい自分のメッセージを確認します。30 秒の期限のうち、入力に 25 秒、ローカル記録の確認に 5 秒を確保します。`RECORDED_LOCAL` はローカル記録の確認だけを意味し、相手への配信や既読を証明しません。同じ `idempotencyKey` で不確かな操作を再確認しても再送せず、読み取り専用で記録を調べます。意図した再送には新しいキーが必要です。

明示した 1 日、または最大 31 日の完全な `dateFrom`/`dateTo` を指定した MCP の読み取り、検索、エクスポート、検証には共通の範囲限定ローカルリーダーを使用します。日付を指定しない従来の操作は、LINE UI に読み込まれた履歴を使用します。`compareWithUi: true` は別の UI 比較を行い、チャットを既読にする場合があります。

独立したチャットウィンドウとファイル選択画面は HWND、PID、タイトルで確認します。`send_file_manual` は添付を選択画面に準備するだけです。承認後に Open を押すと送信されます。Windows 拡張では 26 個のアクティブなツールを表示し、5 個の旧エイリアスは非表示のまま呼び出せます（実装済み記述子は計 31 個）。読み取り専用 `line-cli` と JSON/TXT/CSV 出力は引き続き利用できます。

実際の LINE UI で、個人／グループ送信とローカル記録、青いメンション、引用、転送、取り消し、合成 TXT/PNG 添付とメディア読取、投票、ノート、アルバム、リアクション、通知とウィンドウ切替、スタンプパネルの表示、キャプチャパネルの表示と取消をガイド付きで確認しました。これらは自律的な MCP 実行の検証ではありません。ガイド付き UI で正確なコピーと英語翻訳を確認しましたが、独自描画テキストの直接 MCP 対象選択は拒否される場合があります。Files、Media、Links のガイド付き UI 操作は成功しました。MCP の Files 機能入口は「その他」メニューを開くものの Files 項目を見つけられず `LINE_FEATURE_UNAVAILABLE` を返し、Files パネルは開きません。チャット一覧のピン留めはオフ→オン→オフを確認し、元の状態に戻しました。ダウンロードした TXT ファイルの SHA-256 は元ファイルと完全に一致しました。`get_line_draft` は Search から開いた個人／グループの空の下書きを実機で読み取り、観測時間は約 2.3 秒でした。

GitHub のソースタグと添付の `line-desktop-mcp-3.2.0.tgz` で配布します。npm レジストリと MCPB では配布しません。
