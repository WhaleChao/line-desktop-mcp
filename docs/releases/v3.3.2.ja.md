# v3.3.2 — LINE ウィンドウと検索結果の照合

2026-09-28 (Asia/Taipei)

カテゴリタブは単語単位の OCR で完全一致を確認し、結合された OCR 行をタブと誤認しないようにします。個人チャットの単一結果による画面移動には、完全一致の検索語、選択済み Friends タブ、チャット区画の件数と行が各 1 件であり、別区画のメッセージ履歴の一致をチャット候補と分けること、個別ウィンドウの完全一致タイトルが必要です。メイン LINE ウィンドウは、UIA のナビゲーション列、サイドバー、分割ペイン、境界線、検索欄、リストがすべて揃う場合だけ認定します。曖昧な補助ウィンドウは拒否します。最小化状態からは構造を確認した正確な HWND／PID／タイトルを使って復元し、復元後に再確認します。検索結果の OCR 切り出しには同じ観測済みスクリーンショットを使い、座標を全体画像へ戻します。

依存関係、ツール schema、CLI、再送防止記録は変更しません。Windows では引き続き 33 個の有効なツールと 5 個の非表示旧エイリアスを提供し、不確かな送信結果を自動再送しません。

Node テストは 374／374 件合格。Python は v3.3.1 から変更がなく、以前の 136 件実行・128 件合格・環境によるスキップ 8 件の結果を再利用し、今回は再実行していません。封印済みのセキュリティ差分レビューに報告対象の所見はなく、その後の混在検索差分の独立レビューにも対応すべきセキュリティ欠陥はありませんでした。いずれも今回の変更に限定したレビューです。

ウィンドウのタイトルとローカル DB の身元は独立した証拠であり、HWND と DB の直接対応ではありません。Qt のアクセシビリティ情報は部分的な場合があり、構造が不明確なら拒否します。以前の実機確認では、正確な HWND の最小化状態からの復元、および補助ウィンドウがある状態での個人／グループ検索から完全一致タイトル・空の入力欄までの準備を確認しました。その後の混在する Friends 検索では、チャット結果 1 件と別区画のメッセージ履歴一致 4 件を確認し、空白を含む指定名と完全一致する個別ウィンドウを開いて、ローカルの身元と空の入力欄を再確認しました。クリックしたのは検索、タブ、結果行、個別表示だけで、入力・送信は行っていません。最初のカテゴリ OCR は一時的に拒否しましたが、新たに有効なナビゲーション画面を確認した後の再試行は成功しました。緑色の強調表示だけではチャットの身元を証明できず、あらゆる OCR 表示での成功を保証するものではありません。
