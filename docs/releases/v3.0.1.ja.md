# v3.0.1 — ローカルリーダーのストリーミング修正

[すべての言語](README.md) · [ダウンロード](https://github.com/bensonmaxai/line-desktop-mcp/releases/tag/v3.0.1) · [インストール](../quickstart-windows.md) · [移行とロールバック](../MIGRATING.md#upgrading-to-v301)

![LINE Agent MCP](../assets/line-agent-cover-v3.png)

v3.0.1 は Issue #1 のパッチリリースです。従来の 256 MiB の全ファイル読み取り上限を超えたという理由だけで、ローカルリーダーがデータベースを拒否する問題を修正します。MCP ツール、UI 動作、セキュリティ機能の拡張はありません。v3.0.0 の前提条件と運用上の制限は引き続き適用されます。

## 変更内容

- 暗号化されたデータベース入力を 1 MiB のストリーミングチャンクで読み取ります。既定の予算はデータベース 2 GiB、WAL 256 MiB、結合スナップショット 2304 MiB です。3 つの上限は上限付きの範囲で設定できます。
- コピーしたスナップショットをリーダーが開く前の database/WAL 安定性確認、最新コミット済み WAL の確認、session key の再検証は維持されます。
- リーダーの既定 timeout は 300 秒で、設定可能です。各リクエストは厳密に 1 つの一時ディレクトリを所有し、固定スナップショットファイルは child の終了確認後だけに削除します。終了を確認できない場合、ディレクトリは保持され、クリーンアップ済みとは報告しません。

## 検証と制限

リリース候補は Node テスト 234 件、Python テスト 125 件中 124 件に成功しました。唯一の skip は、テストアカウントで実行できない既存の Windows ファイル symlink 権限テストです。ネイティブ crypto テストはすべて実行しました。853,438,464-byte のデータベースと 4,152-byte の WAL、さらに 1,087,713,280-byte のデータベースと同じ WAL による合成読み取りで、最新コミット済み結果、変更されない source hash、一時ディレクトリの削除を確認しました。これらの fixture での process peak working set は約 39 MiB でしたが、一般的な性能保証ではありません。

リーダーはクエリ前に、対象範囲の source database 全体を引き続きコピーします。ページ単位や日付単位だけのコピーではありません。この検証では build と key discovery を mock しました。実際の LINE チャット読み取り、送信のエンドツーエンド、reporter machine のテストは実行していません。

## アップグレード

GitHub の `v3.0.1` tag、または添付の `line-desktop-mcp-3.0.1.tgz` と `SHA256SUMS.txt` を使用します。npm registry や MCPB には公開しません。新しい同階層ディレクトリに展開し、そのパッケージディレクトリで `npm ci --ignore-scripts` を実行します。launcher を新ディレクトリへ向け、MCP client を再接続して schema を更新してください。LINE database の削除や移行は不要です。ロールバック用に旧パッケージと launcher を残してください。
