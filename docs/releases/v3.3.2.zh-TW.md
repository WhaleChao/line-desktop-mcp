# v3.3.2 — 搜尋與 LINE 主視窗核對

2026-09-28 (Asia/Taipei)

搜尋分類頁籤改用逐字 OCR 精確辨識，避免合併的 OCR 行誤作頁籤。個人聊天室只有在查詢文字完全一致、已選取「好友」頁籤、聊天室區段的計數與列都只有一筆（另列的訊息歷史命中不計入聊天室候選），且開啟後獨立視窗的完整標題完全一致時，才可使用單筆結果的導覽備援。主視窗必須同時具備完整的 UIA 導覽列、側欄、分割窗格、分隔線、搜尋框和清單結構；不明或多個候選視窗會拒絕。最小化視窗只依已證明的精確 HWND／PID／標題恢復，恢復後重新核對。搜尋結果 OCR 裁切自同一張已觀察的截圖，座標會映回完整圖片。

依賴、工具 schema、CLI 行為與防重送紀錄不變。Windows 擴充仍列出 33 個現行工具，另有 5 個隱藏舊別名；結果不確定時不自動重送。

Node 測試 374／374 通過。Python 程式碼與 v3.3.1 相同，沿用先前 136 項執行、128 項通過、8 項環境略過的結果，本次未重跑。已封存的安全差異審查沒有須報告的發現；針對後續混合搜尋差異的獨立審查也沒有可採取行動的安全缺陷。兩者都限於本次變更。

視窗標題與本機資料庫身分是獨立證據，並非直接的 HWND 到 DB 映射。Qt 可及性資訊可能不完整；結構不明或曖昧時會拒絕。先前實機檢查涵蓋精確 HWND 的最小化恢復，以及在其他 LINE 視窗並存時，個人／群組搜尋開啟至標題完全一致且輸入框空白的獨立視窗。後續混合搜尋實測在「好友」頁籤看到一筆聊天室與另列的四筆訊息歷史命中，最後開啟標題與指定名稱完全一致、保留原本空格的獨立視窗，重新核對本機身分及空白輸入框；操作只點搜尋、頁籤、結果列與獨立視窗，未輸入或發送訊息。首次分類 OCR 曾暫時拒絕；取得新的有效導覽畫面後重試通過。綠色標示本身不是聊天室身分證據，也不代表所有 OCR 版面都已驗證。
