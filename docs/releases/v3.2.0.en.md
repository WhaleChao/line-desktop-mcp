# v3.2.0 — Bounded LINE workflows

2026-09-23 · [CLI](../CLI.md) · [Upgrade / rollback](../MIGRATING.md#upgrading-to-v320)

The Windows MCP bridge now checks a plain-text send against a new own message
in the exact chat's local DB/WAL. Its 30-second deadline reserves 25 seconds
for input and five for the receipt check. `RECORDED_LOCAL` means the record
was found locally; it does **not** mean the recipient received or read it.
Persistent idempotency prevents automatic duplicate dispatch. Reuse the same
`idempotencyKey` to inspect an uncertain attempt. An uncertain replay only
checks the local record; a deliberate repeat needs a new key.

One explicit date or a complete `dateFrom`/`dateTo` range of at most 31 days
routes MCP read, search, export, and verify through the shared scoped local
reader. Undated legacy requests still read loaded LINE UI history.
`compareWithUi: true` requests a separate UI comparison and may mark the
chat read. Local cache presence is not a complete server archive.

The bridge binds exact chat identity and own sender identity for sends.
Contact-name collisions refuse even when one candidate has no chat row,
and send identity is refreshed immediately before Return.
Detached windows and file pickers are bound by window handle, process ID, and
title. `send_file_manual` stages an attachment in the picker; the user-approved
Open action sends it. The Windows extension list now shows 26 active tools.
Five legacy aliases remain callable but hidden, for 31 implemented
descriptors. Results are smaller and Ajv loads when extensions are used.
The read-only `line-cli` remains available with its existing scoped
JSON/TXT/CSV commands and does not control LINE.

Live MCP checks exercised dated read, search, and verify at about 0.6 seconds
each in the observed run, plus TXT/JSON/CSV exports with one verified record
each. This is bounded evidence, not a speed guarantee. Guided visual checks
exercised direct and group text sends with local
receipts, a blue mention token, a quoted reply, forwarding and recall,
synthetic TXT/PNG attachment staging and media readback, poll operations,
note and album operations, reactions, notification/window toggles, opening
the sticker panel, and opening then cancelling capture. These rich-feature
actions were guided UI checks, not autonomous MCP tool runs. Custom-drawn
exact copy and English translation passed in guided UI checks, while direct
MCP targeting of custom-drawn text can still refuse. Guided Files, Media,
and Links UI navigation passed. The MCP Files feature entry opens the More
menu but cannot locate Files and returns `LINE_FEATURE_UNAVAILABLE`; it
does not open the Files panel. Chat-list pinning was tested off/on/off and
restored. A downloaded TXT file matched the original SHA-256 exactly.
Live `get_line_draft` read empty direct/group composers after Search/open
in about 2.3 seconds in the observed checks.

Distributed through the GitHub source tag and attached
`line-desktop-mcp-3.2.0.tgz`; there is no npm-registry or MCPB publication.
