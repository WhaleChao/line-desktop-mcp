# v3.3.8 — chat selection, draft checks and detached reply confirmation

Exact-name candidate discovery distinguishes existing conversations from unopened contacts and returns only opaque identity references. A selected unique existing direct chat can be opened with paired chat/account references; multiple existing name-family matches are still refused. A title is not a database-ID or send proof, and bound collisions still require independent visible context before sending.

Draft writes now reuse the same fresh pre-input snapshot for complete-value and expected-draft checks. Matching drafts cause no input; changed drafts retain post-input readback and stale-chat refusal. Optional metrics are disabled by default and contain no chat content or identities. This reduces a redundant snapshot, not a claimed universal speed percentage.

Reply-source confirmation now rechecks the exact previously selected independent chat window instead of requiring the main LINE window. Window replacement, title changes, minimization and changed source pixels remain refusals. Guided Unsend instructions cover the observed background NO-OP, explicit foreground completion and verified Computer Use fallback.

Authorized live checks covered normal direct/group text and TXT sends followed by recall, multiline/emoji draft write/read/clear, identical-draft no-input behavior, draft-conflict preservation, wrong chat/account refusal, repaired reply-source confirmation, guided quoted-draft cleanup and native forwarding-recipient preview/cancellation. [Detailed validation and limits](../VALIDATION_v3.3.8.md).

The custom-drawn Reply menu still required guided selection. Automatic original-forward preparation safely refused when full source OCR could not be verified; guided recipient preview worked and was cancelled without Share. No new quoted reply or forwarded message was sent in the additional batch. These checks do not certify recipient delivery, every LINE UI language, or all guided features.

Package and shrinkwrap root versions are aligned; dependencies are unchanged. No native personal LINE API, native MCP connection, scheduler, global configuration change or background service is added.
