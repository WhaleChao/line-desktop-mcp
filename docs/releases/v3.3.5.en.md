# v3.3.5 — Mixed search category and title OCR

2026-09-29 (Asia/Taipei)

A mixed search showing one chat and separate message hits could still refuse the unique chat: the 30-pixel title crop left too little bottom margin to read the complete name, while edge-clipped OCR separately missed category-header characters or the count. v3.3.5 reads each category from its own UIA-bounded row, uses a 35-pixel title crop, and can add a 16-pixel white margin for OCR. Crop coordinates map back to the original screenshot; out-of-bounds evidence is rejected.

The selected tab, exact query, one chat count, complete name, detached exact title, and local account/chat binding remain required. Send guards are unchanged. This fixes navigation evidence; it does not add a color-based identity check or approve message sending.

Sixty-one related tests passed with zero failures: 54 scoped OCR, exact search, optimized send and send-target tests, plus seven native OCR tests. Five real main-window cold searches across three authorized direct chats reached READY, each with an exact detached title, matching local identity and an empty composer. No message was entered or sent. An independent bounded review found no blocking issue.

Dependencies, public schemas, draft handling and send journals are unchanged. Distribution is a GitHub source tag with attached `.tgz` and `SHA256SUMS.txt`, without npm-registry or MCPB publication.
