# v3.3.2 — Safer LINE window and search binding

2026-09-28 (Asia/Taipei)

The v3.3.2 navigation patch uses word-level OCR for exact category tabs, so merged OCR lines cannot stand in for a tab. A one-result direct-chat fallback requires the exact query, a selected Friends tab, one chat count and one chat row, separated from any message-history hits, and an exact full detached title. The main LINE window must have the complete positive UIA rail, sidebar, split pane, divider, search and list structure; ambiguous auxiliary windows are refused. A minimized window is restored only from a structurally proven exact HWND/PID/title and is checked again after restoration. Search-result OCR crops are taken from one observed screenshot, with crop coordinates mapped back to the full image.

The release changes no dependencies, tool schemas, CLI behavior or send journals. Windows extensions still expose 33 active tools and five hidden legacy aliases. Uncertain send results are never automatically resent.

Node tests: 374/374 passed. Python code is unchanged from v3.3.1; its earlier run had 136 tests, 128 passed and eight environment skips, and was not rerun for this patch. The sealed security diff review found no reportable findings; an independent review of the later mixed-search diff found no actionable security defect. These are focused reviews of the release changes.

Window title and local DB identity remain independent evidence, not a direct HWND-to-DB mapping. Qt accessibility can be partial; ambiguous or unknown structures refuse. Earlier live checks covered exact-HWND minimized restoration and direct/group preparation to exact detached titles with empty composers amid auxiliary windows. The later mixed direct Friends search check had one chat result and four separate message-history hits; it reached the exact requested detached title with the original space retained, refreshed local identity and an empty composer. It clicked search, tab, row and detach only; no message was typed or sent. A first category OCR observation refused transiently; retry after a fresh valid navigation observation passed. The green highlight alone is never chat identity proof, and these observed layouts do not establish success for every OCR layout.
